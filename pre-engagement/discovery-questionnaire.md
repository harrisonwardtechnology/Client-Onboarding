# Discovery Questionnaire

Send this after the qualifying call. Give them a week. Tell them "I do not know" is a real answer and is often the most useful one.

**Roughly forty minutes to fill in.** If it takes them four hours, cut questions.

> Note for buyers reading this: if a consultant is not asking most of this before quoting, they are guessing at your price.

---

## 1. The business

| Question | Answer |
|---|---|
| What does the company do, in one sentence a stranger would understand? | |
| How many people? Full time, part time, contractors | |
| How many locations? Any plants, warehouses, labs, or vehicles? | |
| Roughly what revenue band? (You can say a range) | |
| Who are your customers? Consumers, businesses, government, all three | |
| Are you owned by a PE firm, a parent company, or independent? | |
| Any acquisition, sale, or funding round expected in the next twelve months? | |

**Why:** size and ownership set the whole shape of the program. A PE owned manufacturer with a pending sale needs different work than a bootstrapped software firm.

---

## 2. What brought you here

| Question | Answer |
|---|---|
| What made you start looking for help now? | |
| Is there a date you are working toward? What happens on that date? | |
| Has a customer, insurer, auditor, or investor asked for something specific? Can we see the actual document? | |
| Has anything gone wrong in the last two years? Include the near misses | |
| What did you do about it? | |

**Why:** the deadline and the driver decide priority order. Everything else is preference.

---

## 3. Who decides

| Question | Answer |
|---|---|
| Who is the executive sponsor for this work? | |
| Who can approve spend without asking anyone else? | |
| Who runs IT day to day? Internal, an MSP, or both? | |
| Who owns legal? Internal counsel or outside firm? | |
| Who owns HR? You will need them for people topics | |
| Is there a board, an audit committee, or investors who see security reporting? How often? | |
| Has anyone here ever owned security as their actual job? | |

**Why:** if nobody has ever owned it, do not hand them a program and leave. Build for the people who exist.

---

## 4. What you must comply with

Tick what applies. Add anything missing.

- [ ] Customer contracts with security terms
- [ ] SOC 2 (Type I or Type II, current or wanted)
- [ ] ISO 27001
- [ ] PCI DSS (any card handling at all, including a payment link)
- [ ] HIPAA (any health data, including your own employee health plan data)
- [ ] GDPR or UK GDPR (any EU or UK people, including employees)
- [ ] US state privacy laws (California, Colorado, others)
- [ ] CMMC or DFARS (any defense work, any tier)
- [ ] FERPA or student data
- [ ] NERC CIP, TSA directives, or other sector rules
- [ ] Cyber insurance requirements
- [ ] Nothing formal, but customers keep asking

| Question | Answer |
|---|---|
| Which of the above is actually driving a deadline? | |
| Have you ever been audited or assessed? By whom? What was the result? | |
| Can we see the last report, even if it is embarrassing? | |

**Why:** most companies overstate what applies to them and understate what customers contractually require. The contracts usually bite first.

---

## 5. The environment

| Question | Answer |
|---|---|
| What do people log in with? (Microsoft 365, Google Workspace, Okta, something else) | |
| Where does email live? | |
| Where do files live? | |
| Do you use cloud infrastructure? Which providers? | |
| Do you still run servers in an office or data center? | |
| Do you build software? Is it customer facing? | |
| Do you have a factory floor, lab equipment, building controls, or anything that is not normal IT? | |
| Roughly how many laptops and phones? Company owned or personal? | |
| Is there anything you know is unsupported or out of date? | |

**Why:** you cannot scope work against an environment you have not seen. The last question is the honest one and often the most valuable.

---

## 6. What already exists

| Question | Answer |
|---|---|
| Do you have written security policies? When were they last touched? | |
| Is there an incident response plan? Has anyone read it? | |
| Do you do security awareness training? Does anyone remember it? | |
| Do you have backups? When did you last restore one on purpose? | |
| Is multi factor authentication on for everyone, or just some people? | |
| Do you have a vendor review process before signing? | |
| Do you have a list of your vendors? | |
| Is there a risk register? | |

**Why:** "we have a policy" and "the policy reflects reality" are different answers. Ask when it was last touched, not whether it exists.

---

## 7. Money and effort

| Question | Answer |
|---|---|
| What budget range is this work working within? | |
| Is that budget approved, or does someone still have to approve it? | |
| Is there budget for tools, or only for advice? | |
| How much internal time can you give this? Hours per week, and whose? | |
| Have you budgeted for the work the assessment will find? | |

**Why:** an assessment with no budget behind it produces a document nobody acts on. Ask before, not after.

---

## 8. The honest ones

| Question | Answer |
|---|---|
| What do you already know is broken? | |
| What would embarrass you if a customer saw it? | |
| Who on the team will resist this work, and why? | |
| What has been tried before and failed? | |
| If this goes perfectly, what is different in a year? | |

**Why:** this section is worth more than the other seven combined. People will tell you the truth if you ask plainly and do not flinch.

---

## For the person filling this in

- "I do not know" is a real answer. Write it. It tells us where to look
- Do not clean it up. A tidy answer that is wrong wastes both our time
- If a question does not apply, say so and skip it
- Attach documents rather than summarizing them. We would rather read the real thing
