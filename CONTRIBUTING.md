# Contributing

Corrections and additions are welcome. The goal is that a solo consultant can pick this up and run a clean onboarding on Monday.

## Good contributions

- A question that saved you from a bad engagement
- A question here that turned out to be useless, and why
- Wording that confused a client
- A missing step you learned the hard way
- Plain English replacements for jargon

## House style

- Short sentences. Plain English
- Every item says why it matters. A checklist without reasons gets ignored
- No vendor names unless the point is the category, not the product
- No client data, ever. Not anonymised, not "obviously fake". None
- Markdown only. Tables over prose where a table fits

## How

Open an issue if you want to discuss it first. Open a pull request if you already know what to change. Small pull requests get merged faster than perfect ones.
